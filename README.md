# polynomial-annihilation

A small experiment in lossless compression using polynomial equations over finite fields. The idea is to look for algebraic relations between bytes even when their individual distributions look almost uniform.

## The idea

Say we have records of the form $(a,b,x,y)$ over $\mathbb F_{256}$, where

$$
a=x+y,\qquad b=xy.
$$

We can store $a,b$ and recover $x,y$ by solving

$$
t^2-at+b=0.
$$

The roots are $x$ and $y$. If they are distinct, there are two possible ordered pairs, so one extra bit tells us which pair was in the original record. If they coincide, no extra bit is needed. In the worst case this takes 17 bits per record instead of 32, before storing the equations and other overhead. The arithmetic here is in a finite field, with addition given by XOR in $\mathbb F_{256}$.

The interesting part is finding the equations when we don't know them beforehand.

## Finding the polynomials

Take a set of monomials $m_1,\ldots,m_k$ up to some degree. For each observed record $s_i$, evaluate all of them to obtain a matrix

$$
M_{ij}=m_j(s_i).
$$

Now find its null space over the field. Each nonzero vector $c$ satisfying

$$
Mc=0
$$

gives a polynomial

$$
P(X)=\sum_{j=1}^{k}c_jm_j(X)
$$

that vanishes on the training records. This is what I mean by polynomial annihilation here.

The code tests these relations on separate records and greedily combines equations that reduce the number of possible solutions. For a known context $a$, let

$$
V_a=\{(x,y)\in\mathbb F_q^2:\ P_1(a,x,y)=\cdots=P_r(a,x,y)=0\}.
$$

For a record satisfying the system, we only need to store the context and the index of the actual pair in $V_a$. That index takes $\lceil\log_2 |V_a|\rceil$ bits. Records that don't satisfy the equations are stored explicitly along with an exception mask.

Of course, finding a polynomial is useful only if the space saved is larger than the cost of describing it. The encoder compares actual archive sizes, with a zlib or raw fallback.

## A few tests

All samples are 16 KiB, generated by `benchmark.py` with a fixed seed. Sizes below are in bytes and include the model and archive headers. The entropy column is empirical **single-byte** entropy, in bits per byte.

| Dataset | Bytes | Byte entropy | gzip | bzip2 | xz | zlib | Polynomial | Mode |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| Sum and product | 16384 | 7.9894 | 16275 | 16804 | 16444 | 16263 | 8845 | system |
| Sum and product (1% noise) | 16384 | 7.9894 | 16278 | 16804 | 16444 | 16266 | 9078 | system |
| AES field inversion | 16384 | 7.9871 | 16278 | 16715 | 16444 | 16266 | 8362 | system |
| AES MixColumns | 16384 | 7.9884 | 16407 | 16843 | 16444 | 16395 | 12467 | system |
| Uniform random bytes | 16384 | 7.9907 | 16407 | 16845 | 16444 | 16395 | 16397 | raw |
| SHA-256 digests | 16384 | 7.9874 | 16407 | 16855 | 16444 | 16395 | 16397 | raw |

The first dataset is the sum/product example above. In the noisy version, about 1% of the records have one output bit flipped. The AES examples contain both inputs and outputs of individual intermediate transformations, not encrypted messages. For instance, the inversion example yields the recovered system

$$
a^2x+a=0,\qquad b^2y+b=0.
$$

For nonzero inputs this determines $x=a^{-1}$ and $y=b^{-1}$. At zero, the equations leave the corresponding output free, so the encoder stores its index as usual.

The random and SHA-256 samples serve as controls. Neither yielded a useful model in this search. Near-maximal byte entropy alone doesn't imply that the joint distribution is uniform: if $X$ is a uniform byte and $Y$ is its field inverse (with zero mapped to zero), then $H(X)=H(Y)=8$ but $H(X,Y)=8$ as well. There is no contradiction with Shannon's source coding theorem.

## Running it

Python 3.10+ and NumPy are enough.

```sh
pip install -r requirements.txt
python benchmark.py
```

The benchmark prints the table and the recovered equations, and checks that each compressor returns the exact original bytes. gzip and zlib use level 6, bzip2 uses level 9 and xz uses preset 6.

To try a file yourself:

```sh
python annihilation.py encode input.bin output.pan
python annihilation.py inspect output.pan
python annihilation.py decode output.pan restored.bin
```

`annihilation.py` contains the search, finite-field operations, root enumeration and codec. `benchmark.py` generates the examples and compares the sizes.

## Scope

This is a small extract from the SYZYG experiments, with a standalone archive format. It searches fixed-width records over $\mathbb F_{251}$, $\mathbb F_{256}$ and $\mathbb F_{257}$ (the last uses little-endian 16-bit symbols), with two unknowns, degrees up to three (at most quadratic in the last unknown) and up to four equations. The search is bounded and can miss relations. The examples are intentionally small, mostly constructed with known dependencies; the results don't establish general superiority over other compressors or a weakness in AES or SHA-256. The code is meant for experimentation with trusted inputs, not production use.
